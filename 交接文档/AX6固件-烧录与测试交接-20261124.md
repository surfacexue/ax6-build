## 1. 拿产物

1. 打开 <https://github.com/surfacexue/ax6-build/actions>
2. 点最新一轮（成功的那个），页面底部 **Artifacts** → `ax6-nss-wireguard-firmware.zip`
3. **下载 artifact 需要登录 GitHub**（匿名只能读接口元数据，拿不到 zip）

zip 里有 5 类文件（名字都以 `openwrt-qualcommax-ipq807x-redmi_ax6-stock-squashfs-` 开头，用通配匹配更保险）：

```
*sysupgrade.bin        ← 刷这个
*factory.ubi
sha256sums
config.buildinfo
openwrt-qualcommax-ipq807x-redmi_ax6-stock.manifest   ← 装了哪些包，grep 比拆镜像快
```

**先验哈希，再验内容——不要只看 Actions 绿灯。**

```python
import zipfile, hashlib
z = zipfile.ZipFile('ax6-nss-wireguard-firmware.zip')
print(z.read('sha256sums').decode())
for n in z.namelist():
    if n.endswith(('.bin', '.ubi')):
        print(n, hashlib.sha256(z.read(n)).hexdigest())
```

与 `sha256sums` 逐字节对比。注意：**不同轮次的 sha256 必然不同**（buildid、时间戳），要判断两轮产物是否等价，比 `*.manifest` 而不是比哈希。

证明包真在镜像里（`sysupgrade.bin` 前面的 boot/kernel 偏移不固定，用 `hsqs` 魔数定位 squashfs）：

```python
import zipfile
from PySquashfsImage import SquashFsImage

z = zipfile.ZipFile('ax6-nss-wireguard-firmware.zip')
d = z.read([n for n in z.namelist() if n.endswith('sysupgrade.bin')][0])
open('root.squashfs', 'wb').write(d[d.find(b'hsqs'):])

img = SquashFsImage.from_file('root.squashfs')
byp = {i.path: i for i in img}
for p in ['/lib/modules/6.12.31/wireguard.ko',
          '/usr/bin/wg',
          '/lib/netifd/proto/wireguard.sh',
          '/usr/lib/rpcd/wireguard.so',
          '/usr/sbin/tailscaled',
          '/etc/init.d/tailscale']:
    print('%-46s %s' % (p, byp[p].size if p in byp else '不存在'))
```

判定：`wireguard.ko` 与 `tailscaled` 都在、`/etc/init.d/tailscale` 在（说明 procd 能托管开机自启）。

## 2. 刷机

设备是 redmi_ax6**-stock**（原厂分区布局），产物的 sysupgrade 就是给这个布局用的。

1. 解压 zip，取出 `...-squashfs-sysupgrade.bin`。**sysupgrade 只认 `.bin`，传 zip 会报错。**
2. 进 LuCI（默认 `192.168.1.1`）→ 系统 → 备份/升级 → 刷写固件，选这个 `.bin`。
3. **不保留配置**（`sysupgrade -n`）：这次是从别的 fork 过来，带着旧配置刷最容易出各种怪问题。
4. 刷完设备地址是 `192.168.1.1`，浏览器设一次 root 密码。

> 原作者交接文档里提到的自动恢复脚本（`G:\soft\AX6刷机\_tools\3-自动恢复配置.bat`、`_tools/naswan-pkg/restore-rule.sh`、`deploy.sh`）是**他那台机器上的路径**，本机与家里机器都未必有。没有就手工配，别去找那个盘符。

## 3. 刷后验收（设备侧，逐条跑）

```sh
uname -a                                # 内核应为 6.12.31
lsmod | grep wireguard                  # 应看到 wireguard
wg --version                            # 应输出版本号
tailscale version                       # 应有输出；没有就是没进镜像
ls -l /etc/rc.d/S*tailscale             # 存在=开机自启；不想常开：/etc/init.d/tailscale disable
cat /etc/openwrt_release                # 确认发行版与版本
```

再确认 NSS 相关的东西真的在跑（这是这套固件相对官方固件的全部意义，值得单独看）：

```sh
lsmod | grep -i nss                     # qca-nss-* 一类模块
dmesg | grep -i nss | tail -30          # 初始化/固件加载的报错都在这里
cat /proc/interrupts | grep -i nss      # NSS 队列中断是否挂上
```

WiFi 与隧道各自单独验一遍：

```sh
iwinfo | grep -E 'ESSID|Mode|Signal'    # 两个 radio 都要起来
ip -6 addr show tailscale0              # 登录 tailscale 后应有 100.x 地址
wg show                                 # 配好 peer 后应列出 endpoint 与握手时间
```

判定口径：**内核版本对、wireguard 模块在、tailscaled 在、NSS 模块加载无报错、两个 radio 正常、隧道能握手**——六条全过才算刷成功。

**P0 补丁三处**（这是从失败轮里买来的教训，别改回去）：

1. **ccache 路径**：`/mnt/ax6build/.ccache` → `/mnt/ax6build/openwrt/.ccache`。源码树 `rules.mk` 第 355 行是 `$(if $(CONFIG_CCACHE_DIR), …, $(TOPDIR)/.ccache)`，而 `ax6.config` 里 `CONFIG_CCACHE_DIR=""`，所以真实落盘在 `$(TOPDIR)/.ccache`。写错时缓存每轮传上去都是空目录——`ccache-45031381400`、`ccache-45284063911` 都是 0.00 GB，就是铁证。
2. **串行重试限时**：失败后的重试改成 `timeout 45m make -j1 V=s`，避免一轮卡满 350 分钟超时。
3. **诊断步骤**：三个 `if: failure()` 改成 `if: failure() || cancelled()`（被 cancel 时也要留日志），诊断正则加 `ERROR:|failed to build|Collected errors`，`missing dependencies` 锚定为 `^Package .* is missing dependencies`（命中从 85 条噪音降到 10 条）。

**run #11 的两处新改动**：

- 新增第 12 步「恢复 dl 缓存」：`path: /mnt/ax6build/openwrt/dl`，`key: dl-${{ hashFiles('ax6.config') }}-${{ hashFiles('.github/workflows/build.yml') }}`，`restore-keys: dl-`。用精确 key 是为了命中时不产生新归档（`dl/` 内容在仓库状态不变时也不变），前缀回退是为了改了 config 后仍能捞回旧 tarball、`make download` 只补缺的。

## 5. 关键结论与坑（都是实测过的）

**耗时（同一棵树，五轮实测）**

| run | 提交 | 编译 | 整 job | 说明 |
| --- | --- | --- | --- | --- |
| #8 | `dba6c59` | 89.1 分钟 | 97.4 分钟 | ccache 路径错误，缓存为空 |
| #9 | `3dec28f` | 82.8 分钟 | 95.5 分钟 | 路径修好，缓存首次播种 269.9 MB |
| #10 | `0dd84af` | **62.7 分钟** | **74.4 分钟** | 首次真命中：**省 20.1 分钟（−24%）** |
| #11 | `3d4401a` | 进行中 | — | 给 dl 缓存播种，收益要到 #12 才显现 |

ccache 归档稳定在 0.27 GB 量级（#9 269.9 MB → #10 272.1 MB，只涨 2.2 MB，说明该树编译单元基本都进缓存了）。这是 zstd 压缩后的归档体积，不是 `.ccache` 目录真实体积。

**缓存的边界**

- `actions/cache` 是**路径级、整包**：没有文件级增量比对，只缓存子目录就得在 `path` 里逐个点名。
- **`staging_dir` 不能单独缓存**：决定「要不要重编」的是 `build_dir` 里的 stamp——`STAMP_BUILT = $(PKG_BUILD_DIR)/.built`、`STAMP_CONFIGURED = $(PKG_BUILD_DIR)/.configured_<config 取值>`。`staging_dir` 只是安装目的地，单独恢复它，`make` 照样从头编一遍再覆盖回来。真要缓存构建状态必须 `build_dir` + `staging_dir` 成对，那是十几 GB，超仓库 10 GB 配额。
- 仓库缓存配额默认 10 GB，连续 7 天未被引用的条目自动清。

**编译环境**

- `runs-on: ubuntu-22.04` 只给一台干净虚拟机，**GitHub 不读 `.config`**，也不会按 config 装东西。依赖由第 5 步 apt 装（`build-essential clang flex bison gcc-multilib libncurses5-dev libssl-dev python3-distutils rsync ccache time` 等），交叉工具链由 OpenWrt 源码树在 `make` 里自建（`staging_dir/toolchain-aarch64_cortex-a53_gcc-14.3.0_musl`）。
- 为什么是 22.04：依赖清单里的 `python3-distutils` 在 24.04 已被移除，`libncurses5-dev` 也只剩 `libncurses-dev`，24.04 上那行 apt 直接失败。

**触发与观察**

- 推 main 且改动命中 `ax6.config` 或 `.github/workflows/build.yml` 才编译；空提交不触发。SSH push 就够，不需要网页登录。
- `concurrency: cancel-in-progress: true`：编译期间再推这两个文件之一，**正在跑的 job 会被立刻取消**。
- `Re-run all jobs` 按钮走 REST，需网页登录或 PAT；SSH 代理帮不上。
- 匿名 GitHub API 限 60 次/小时，轮询间隔 10 分钟才安全（我两次把监控脚本打死在 `KeyError: 'jobs'`）。
- 日志下载要 token；失败日志会自动推 `logs` 分支（`git push -f`，只留最近一次）。

**镜像体积**

- 编译期没有 IMAGE_SIZE 检查：`image.mk` 只对 `KERNEL_SIZE` 做 check-size，而该设备把 `KERNEL_SIZE` 清空了。
- 真正的上限在 `ipq8071-ax6.dts` 的 `reg = <0x2dc0000 0x5220000>` ≈ **82.4 MB**。sysupgrade 超过这个数，刷上去会启动失败。
