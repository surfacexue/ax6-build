## 本机事实（决定了上面"能直刷"一列）

2026-11-24 实测：

```
board_name : redmi,ax6-stock
model      : Redmi AX6 (stock layout)
MemTotal   : 401900 kB
mtd12      : 06640000 (102.25 MiB) "rootfs"      ← 只有一个 rootfs，没有 kernel 分区
固件       : ImmortalWrt SNAPSHOT r35452+21-42d80a41c9（内核 6.12.40）
```

**命名陷阱**：`-stock` 不是"原厂小米固件"，而是指**单卷 UBI 布局**（custom U-Boot，大分区）：

| 设备名 | 分区 | 说明 |
|---|---|---|
| `redmi_ax6` | kernel 36 MB + rootfs 双卷 | 对应 `DEVICE_VARIANT := (OpenWrt expand layout)`，原厂首次 ubiformat 用 |
| `redmi_ax6-stock` | 单卷 rootfs（102 MiB） | 对应 `DEVICE_ALT0_VARIANT := (custom U-Boot layout)`，**本机就是这种** |

这条决定生死：镜像的 `DEVICE_` profile 与本机 `board_name` 不一致时，sysupgrade 会拒刷；
`-F` 强刷能写进去但起不来。

## 1. JuliusBairaktaris/Qualcommax_NSS_Builder

- 不是源码树，是**预编译发布站 + 构建器**：从 `openwrt-ppe-nss` 的 `ppe-nss` 分支编 41 个
  IPQ807x 板子（含 Redmi AX6），产物在 Releases 与 `ppenss.github.io`（可在线选包）。
- 内核：`target/linux/generic/kernel-6.18` → `LINUX_VERSION-6.18 = .64`（6.18 系列，非 6.12）。
- 架构与 qosmio 那套不同：**有线走 PPE（交换机包引擎）+ EDMA，无线走 `nss-wifi-drv`；
  没有 ECM、没有 qca-nss-drv 主机驱动**。它自己也这么写："There is no ECM, no NSS qdisc and
  no vendor NSS host driver."
- 设备支持：`target/linux/qualcommax/image/ipq807x.mk`（678 行）里**只有 `Device/redmi_ax6`，
  没有 `redmi_ax6-stock`**；而 `redmi_ax6` 继承 `Device/xiaomi_ax3600` 的 `KERNEL_SIZE := 36608k`
  → 产物是 kernel+rootfs 双卷。`devices/ipq807x-512m/config` 第 18 行也确认是
  `CONFIG_TARGET_DEVICE_qualcommax_ipq807x_DEVICE_redmi_ax6=y`。
- 最近提交：2026-11-22（活跃）。工程质量是这几个里最高的：GCC 15 + LTO + PIE/SSP、
  自带 kmod feed、`ppe-update` 自更新、OpenSSH + HTTPS 默认开、BCP38 默认开。
- 只有 sysupgrade，**没有 factory 镜像**：要求先有 stock OpenWrt 再刷。

**怎么用（关键）**：本机现在是单卷布局，刷不进去。**如果哪天把分区刷回 `redmi_ax6`
双卷布局（kernel 36 MB + rootfs），它现成的 AX6 镜像就能直接 sysupgrade**，
这就是它的价值：不用自己编，跟着上游更新。前提是先把 ART / U-Boot / 整片 NAND 备份好，
并且接受"改回双卷"这个不可逆操作（改分区表要动 U-Boot）。

**不建议**直接改它的 devices 定义来适配单卷：那要自己补 `redmi_ax6-stock` 并验证
PPE 在新布局下的 `platform.sh` 升级逻辑，工作量≈在 qosmio 树里已经做过的事。

## 2. massivehard2014/ax6-nss-pure

- 仓库只有三个文件：`.github/workflows/build.yml`、`configs/redmi-ax6-pure.config`、README。
  源码是 `LiBwrt/LibWrt` 分支 `25.12-nss`。
- config 实测内容：`DEVICE_redmi_ax6-stock=y`、NSS 核心三件套 + ECM + `nss-firmware-ipq807x`、
  `kmod-qca-nss-drv-{pppoe,bridge-mgr,vlan-mgr,qdisc,igs,tun6rd,tunipip6,gre,pvxlanmgr}`、
  `NSS_MEM_PROFILE_MEDIUM`、`NSS_DRV_WIFI_OFFLOAD_ENABLE`，无代理插件。
- 最近提交：2026-11-21。
- **README 的刷机警告是错的**：它说"本固件适配 custom U-Boot layout，原厂 AX6 不能直刷，
  要先刷过渡固件换 U-Boot"。它把 `DEVICE_ALT0_VARIANT := (custom U-Boot layout)` 这行
  当成了实机前置条件。实际含义是"同一个板子也可以叫这个名字"；本机 board_name 正是
  `redmi,ax6-stock`，**不需要换 U-Boot**。作者对布局的理解有偏差，其余段落也要自己核。
- 价值：**NSS 核心段可以直接抄**（我们 `libwrt/configs/libwrt-ax6.config` 就是抄的这段），
  其余功能包缺 wireguard / tailscale / luci-ssl / argon / openclash，得自己补。

## 3. Steven-ZYC/AX6-OpenWrt-Tiny

- 基于 Julius 的 `openwrt-ppe-nss`，**固定提交 `7d65a3e`**，内核 6.18，出两个版本：
  Tiny（精简）与 Tiny Plus（加 HomeProxy + sing-box-tiny）。
- **设备定义明确写 `DEVICE_redmi_ax6-stock=y`**，并且构建时校验 factory UBI ≤ 28 MiB；
  仓库里 `scripts/prepare-ppe-experiment.sh` 就是补单卷布局那一步 —— 正好补上第 1 节缺的。
- 最近提交：2026-11-14；RC2 发布同日，README 称已在原厂分区实机测过。
- 实测 config（Tiny stock 版，56 行）里：`kmod-nss-wifi-drv`、`nss-firmware-ipq807x`、
  `wpad-openssl`、`luci-ssl`；**没有 wireguard、没有 tailscale、没有 argon**，
  `# CONFIG_PACKAGE_qca-nss-ecm is not set`（PPE 架构本来不用 ECM）。
- 结论：**想今晚就尝 6.18 新内核，它最省事（直接下 sysupgrade 刷）**；
  想保留本机现有功能（tailscale / WireGuard / openclash / argon），它不合适 —— 28 MiB 的体积
  上限装不下 tailscale（安装后 20.5 MB）。

## 4. llz121517/immortalwrt-ax6-nss

- 目标同样是 `redmi,ax6-stock`，但面向**改机 1G/1G**：`ATH11K_MEM_PROFILE_1G=y`，
  U-Boot 分区是 kernel 45 LEB（5.4 MiB）+ rootfs 240 LEB（29 MiB）。
  本机是无 kernel 卷、rootfs 102 MiB、RAM 392 MiB → **镜像不能刷**。
- 但它做的事和我们要做的完全同构：在 ImmortalWrt 25.12（**内核 6.12.116**）上移植
  qosmio 的 NSS/ECM（20 个内核钩子补丁）+ 97 个 ath11k/mac80211 NSS 补丁。
- 最近提交：2026-11-12。
- **文档价值最高的四条**（都已吸收进本仓库的配置与验收流程）：
  1. **nft flow offloading 必须关**，否则 fw4 的 flowtable 抢走已建连接、ECM 看不到回程，
     `accelerated_count` 永远是 0。→ 已写入首启脚本 `files/etc/uci-defaults/99-nss-offload`
  2. 判据是 `accelerated_count > 0` + `ecm_dump.sh` 里 `accel_mode=2`，
     **不是** `nf_conntrack` 的 `HW_OFFLOAD`（qca-nss-ecm 不走 `nf_flow_table`，那个恒为 0）
  3. **fullcone 与 NSS offload 有冲突面**：`accel_mode` 不进 2 时先关 fullcone 对比
  4. 补丁验证只认 `make package/kernel/mac80211/prepare`（默认 fuzz 2），`patch -p1` 会误报
- 建议：当**验收手册**收藏，不刷它的镜像。

## 6. VIKINGYFY/immortalwrt

- 自用 ImmortalWrt 改版（"AI Edition"），分支说明：`owrt` 为多平台通用，
  MTK / QCA / QCB 带满血 PPE 驱动。源码拼自 `JiaY-shi/openwrt`、
  `JuliusBairaktaris/openwrt-ppe-nss`、`pbs05/ponwrt`、`perceival/openwrt-flint3`。
- 特点：走 **PPE**（与第 1、3 节同一技术路线，不是 qca-nss-drv/ECM），
  README 顶部带中转站推广位；配套改版插件在 `VIKINGYFY/packages`，工具在 `OWRT-Tools`。
- 评价：**个人自用改版 + 多来源拼装**，优点是 PPE 支持面广、有现成 CI 模板
  （`VIKINGYFY/OpenWRT-CI`）；缺点是上游血统混杂、无设备适配说明、推广位明显。
  **不建议作为长期基线**；如果以后要走 PPE 路线，直接跟 `JuliusBairaktaris/openwrt-ppe-nss`
  更干净。
