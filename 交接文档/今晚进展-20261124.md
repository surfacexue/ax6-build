## 四、关键决策与依据

### 1. 为什么切 NSS 12.5（Release 210）

`nss-packages` 的 `NSS-12.5-K6.x` 分支里 `qca-nss-drv/Makefile` 只有一段降级逻辑：

```make
PKG_SOURCE_DATE:=2024-11-13
PKG_SOURCE_VERSION:=d5ee67b
QSDK_VERSION:=12.5
ifeq ($(CONFIG_NSS_FIRMWARE_VERSION_11_4),y)
  PKG_SOURCE_DATE:=2021-09-13
  PKG_SOURCE_VERSION:=53e5863
  QSDK_VERSION:=11.4.0.5
endif
```

即 **一个 Kconfig 开关同时换 fw 和 drv**。现系统是 `ECM 12.5.2024.11.06 + DRV/FW 11.4`（dmesg `NSS.HK.11.4.0.5-6-R`）的跨版本混搭，切 12.5 后三者版本对齐。

代价：12.x 全系不支持 802.11s NSS mesh（`nss-firmware` Makefile help 明写）。本机不用 mesh，可接受。

### 2. 为什么 12.5 的改动放在分支、不进 main

`build.yml` 的 `paths` 含 `ax6.config` → push 到 main 会**自动触发编译**；而 `concurrency.cancel-in-progress: true` 会把正在跑的 #12 直接取消。#12 已进入编译阶段，不值得打断。

所以：`main` 保持 11.4，12.5 放分支 `nss-fw-12.5`。

> ⚠️ 手动触发主线时**不要选 main**：ref 与 #12 相同，会撞并发把 #12 掐掉；且 main 上仍是 11.4。要跑 12.5 就选 `nss-fw-12.5`。

### 3. 为什么建第三条线（B 方案）

二线 LibWrt 解决"内核新 + 原生 stock 支持"，但加速仍是 ECM；三线 PPE-NSS 走另一套架构（PPE/EDMA），是唯一的对照组。三条线产出的固件用同一套验收判据比较，才能判断哪套加速在本机真正有效。

### 4. meshmgr 不是雷（已核实）

`ax6.config` 里有 `CONFIG_PACKAGE_kmod-qca-nss-drv-wifi-meshmgr=y`，但 `qosmio/nss-packages` 的 NSS-12.5-K6.x 分支**没有**定义这个 KernelPackage（顶层只有 firmware / nss-ifb / nss-userspace-oss / qca-mcs / cfi / clients / crypto / drv / ecm / macsec / ssdk-shell）。所以那行是残留项，buildroot 直接忽略，切 12.5 不会因此编译失败。

## 六、今晚纠正过的误判（避免后人重犯）

1. **"已编固件是升级"→ 实际是降级**：6.12.31 < 6.12.40、mac80211 6.12.6 < 6.14.11、344 < 368 包。所以放弃沿用旧产物，改换源码树。
2. **"Tiny 没有 argon"→ 有**：`redmi-ax6-stock.config` 第 15 行 `luci-theme-argon=y`。别凭印象下结论，先 grep。
3. **"缺 thermal、要加 kmod-thermal"→ 不需要**：`CONFIG_THERMAL=y` 在 `target/linux/qualcommax/config-6.12`，且无 `kmod-thermal` 这个包。
4. **"缺 fullconenat"→ 包名是 `fullcone`**（少个字母），`kmod-nft-fullcone` 早已 `=y`。
5. **README 曾写"`-stock` 是原厂分区"→ 表述已改**：`-stock` 指单卷 UBI 布局，`redmi_ax6` 是 kernel 36MB + rootfs 双卷 expand 布局。**两者误刷即砖**，这是全项目第一号陷阱。
6. **12.5 与 11.4 不是"新固件包"，是同一套包里的 Kconfig 选择**：`nss-firmware` 2025.05.01 内含 11_4 R6 / 12_1 / 12_2 / 12_5 R210 四套。

## 七、验收判据（刷完后按此验，别只看 nf_conntrack）

来自 llz121517 的实测结论：

1. **必须先把 `flow_offloading` 设为 0**，否则测不出 NSS 加速；
2. 看 `/sys/kernel/debug/ecm/ecm_db/...` 的 `accelerated_count > 0`；
3. 且 `accel_mode = 2`；
4. **不是**看 `nf_conntrack` 的 `HW_OFFLOAD` 标志（那是另一套机制）。
