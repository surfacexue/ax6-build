### config 包里有什么

`sysupgrade -b` 打的是「配置 + 少量自加文件」的标准集合，实际覆盖：

- `/etc/config/*`：`network`、`dhcp`、`wireless`、`firewall`、`openclash`、`mosdns`、`sqm`、`turboacc`、`upnpd`、`ddns` 等
- `/etc/dropbear/authorized_keys`（免密登录凭据）
- `/etc/crontabs/root`（含自动重启那一条，见第七节）
- `/etc/rc.local`、`/etc/passwd`、`/etc/shadow`、`/etc/hosts`

### extras 包为什么单独打

`sysupgrade -b` **不收录**以下三处，但都是这台机器上手工加过的：

```

root/luci-duid-patch.sh       LuCI DHCP DUID 显示的补丁脚本
root/bak-duid-20261122/       打补丁前的原件：dhcp.orig、40_dhcp.js.orig
```

## 三、备份前怎么验（复用这套流程时照做）

三条要点，缺一条就可能拿到截断的备份而不自知：

**1. SSH 必须用 Windows 自带的 ssh.exe**

Git Bash 的 ssh（MSYS）连不上 Windows 命名管道 `\\.\pipe\openssh-ssh-agent`，密钥在 Bitwarden 桌面版的 SSH Agent 里也取不到。

```bash
SSH=/c/Windows/System32/OpenSSH/ssh.exe
$SSH -o BatchMode=yes ax6 'echo OK'
```

私钥带口令，认证由 Bitwarden 提供；**不要**启动 Windows 自带的 `ssh-agent` 服务，两者会抢同一个管道。

**2. 先核对分区，再决定读哪个 mtd**

```bash
$SSH -o BatchMode=yes ax6 'cat /proc/mtd; echo $((0x06640000))'
```

`mtd12` 必须是 `"rootfs"` 且大小为 `107216896`。若与本文档不符，说明设备已不是备份时那台/那版，停止操作。

**3. 拷回来后必须双向哈希**

```bash
$SSH -o BatchMode=yes ax6 'sha256sum /dev/mtd12'   # 路由器侧
sha256sum mtd12-20261125.bin                        # 本机
```

两边一致才算完成。**只算本机一侧没有意义**——传输截断时本机算出来的哈希同样“自洽”。

字节数同样要卡死：`ls -l` 必须正好 `107216896`。

**4. 传输用 Git Bash，不要用 PowerShell 重定向**

PowerShell 的 `>` 默认 UTF-16，会毁掉二进制文件。命令形态：

```bash
$SSH -o BatchMode=yes ax6 'cat /dev/mtd12' > mtd12-20261125.bin
```

107 MB 约 16 秒。

## 四、回滚方法（按风险从低到高）

### 方案 A：只回配置（刷完新系统，功能不对）

最常见。新固件能启动、能上网，但配置丢了或者不对：

```bash
scp config-20261125.tar.gz root@192.168.1.1:/tmp/
ssh root@192.168.1.1 "sysupgrade -r /tmp/config-20261125.tar.gz && reboot"
```

`sysupgrade -r` 是「恢复配置」，与 `-f`（刷固件）不同，不写 flash 的固件区。

手工改动另外补：

```bash
scp extras-20261125.tar.gz root@192.168.1.1:/tmp/
ssh root@192.168.1.1 "cd / && tar xzf /tmp/extras-20261125.tar.gz"
```

> 注意：如果刷机时用了 `-n`（清空 `/etc/config`），恢复配置后**部分包可能起不来**，因为新固件的包集合与旧配置不一定对得上（例如旧配置里有 `openclash`，新固件没装）。恢复后逐项检查 `logread | tail -50`。

### 方案 B：刷回原固件（新固件能启动，但不想用）

如果手上有同版本的 sysupgrade 镜像，走正常刷机路径即可，不需要动 mtd12。
这条路径依赖「新系统还能进 LuCI/SSH」，能进就别用方案 C。

### 方案 C：整片写回 mtd12（新系统起不来，但还能进 SSH/救砖模式）

**这条没有在真机验证过，属于最后手段。** 原理是把备份的 102.25 MiB UBI 原样写回 rootfs 分区。

关键限制：**运行中的系统上，`mtd12` 正被 UBI 挂载，`mtd write` 会报 device busy 失败**；强行写会撕裂 UBI，比不写更糟。所以必须满足以下之一：

- 从 **initramfs** 启动（内存系统，不挂载 flash），再 `ubiformat /dev/mtd12 -f mtd12-20261125.bin`
- 或者走 **U-Boot 恢复模式**（见方案 D）

在正常系统里能做的只有把文件传上去：

```bash
# 仅传文件，这一步是安全的
scp mtd12-20261125.bin root@192.168.1.1:/tmp/
```

真正的写入要等进 initramfs 或 U-Boot 之后再做。

### 方案 D：U-Boot 恢复（系统完全起不来）

小米 AX6 的 U-Boot 带网络恢复，通常的形态是：

```
PC 静态地址 192.168.31.2/24  →  设备恢复模式地址 192.168.31.1
用小米路由器修复工具，或 tftp 上传 factory 镜像
```

**这个 31.1/31.2 的地址请在上机前自行确认一次**（不同 U-Boot 版本可能不同），别等出事时才现查。

注意本机的 U-Boot 只有 `flag_ota_reboot` 和 `flag_boot_success` 两个环境变量，**没有 `flag_boot_rootfs`**——即单槽，没有 A/B 回退。这也是「刷错设备定义就变砖」的直接原因。

## 五、刷机前检查清单

- [ ] `mtd12-20261125.bin` 在本机和 NAS 都有，字节数 `107216896`，sha256 对得上
- [ ] 固件是 **`redmi_ax6-stock`**，不是 `redmi_ax6`（`CONTROL` 里 `BOARD=redmi_ax6-stock`）
- [ ] 固件来源是 NAS 本地文件，不是边刷边从网上取
- [ ] 用**网线**，不用 WiFi；不用排插上带其他负载的插座
- [ ] AX6 已从家里主网络断开，接在独立交换机上（避免它的 DHCP 进入家庭二层）
- [ ] PC 已设静态地址（如 `192.168.1.10/24`，网关留空），或加了辅助 IP
- [ ] 避开 03:00（见第七节）

刷完的验收判据（ECM 线）：

```sh
# 1) 转发必须走软件路径，否则 ECM 不接管
uci get firewall.@defaults[0].flow_offloading        # 期望 0

# 2) 有流量经过后看加速计数
cat /sys/kernel/debug/ecm/ecm_db/accelerated_count   # 期望 >0

# 3) 加速模式
cat /sys/kernel/debug/ecm/ecm_db/defunct_count
```

判据核心：`flow_offloading=0` + `accelerated_count>0` + `accel_mode=2`。
**不要**用 `nf_conntrack` 的 `HW_OFFLOAD` 标记判断——那不是 ECM 的路径。

## 六、这次备份踩到的两个坑（供以后复用）

**1. 公钥没生效不是路由器的问题，是 ssh 客户端选错了**

现象：`Offering public key` 之后 `Permission denied (publickey,password)`。
真因：Git Bash 的 ssh 看不到 Bitwarden 的 agent 管道，取不到私钥去签名。
换 `/c/Windows/System32/OpenSSH/ssh.exe` 后一次通过。
排查成本很高，因为报错看起来完全像「服务端没配公钥」。

**2. `sysupgrade -b` 不等于「全部配置」**

它只收 `/etc/config`、`/etc/dropbear`、`/etc/crontabs` 等固定清单，**自定义脚本目录（如 `/etc/ddns/`）和 `/root` 下的文件都不在里面**。这次是靠 `find /etc /usr -newermt "2026-11-20"` 找出来的。

## 七、一个必须避开的时间点

`/etc/crontabs/root` 里有：

```
0 3 * * 2,4,0  sleep 200 && touch /etc/banner && reboot
```

**每周二、四、日 03:00 自动重启**（`sleep 200` 后执行）。这条在配置备份包里，刷机若带 `-n` 则不会自动恢复。

刷机窗口若跨过 03:00，会被这次重启打断。凌晨刷机请留足余量，或提前 `crontab -e` 注释掉。

## 八、禁止事项

- **不要**用 `mtd write` 在运行中的系统上写 `mtd12`（UBI 已挂载，必失败且可能撕裂）
- **不要**把 `redmi_ax6` 的双卷固件刷到本机（单槽，刷错即砖）
- **不要**在没核对 `/proc/mtd` 的情况下按「记忆中的分区号」操作
- **不要**用 PowerShell 的 `>` 做二进制重定向
- 备份已经做完，后续任何写 flash 的操作都需要单独确认，不能因为「有备份」就放松
